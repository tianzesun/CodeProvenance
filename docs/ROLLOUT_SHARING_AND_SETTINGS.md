# Rollout: course sharing, workspace settings and notifications

Covers the changes on branch `fix/benchmark-plugin-and-typecheck` (PR #9).

## What changes for users

- **Courses, analyses and cases are private to their instructors.** Others see them only when an
  owner shares them (with chosen colleagues or the whole organization). Existing items become
  private on upgrade.
- **Each workspace's settings apply to that workspace only** (AI provider and keys, email, limits,
  scoring weights). They used to leak between workspaces on a shared server.
- **Saved API keys and passwords are encrypted** (AES-256-GCM) and can be removed from the
  settings page.
- **New:** previous-term matching, email and webhook notifications when an analysis finishes, a
  fallback AI provider, and quick-setup presets on the settings page.

## Deploy steps (production)

1. Back up the database.
2. Add `SETTINGS_ENCRYPTION_KEY` to the environment from the managed secret store (base64 of
   32 random bytes; see `docs/ENVIRONMENT_SETUP.md`). Keep it: losing it makes every saved
   workspace credential unreadable. `deploy/setup.sh` reuses an existing key on re-runs.
3. Deploy the code, then run the migrations. They add `resource_shares`, plus the case columns
   (`priority`, `investigator_id`, `closed_at`) and `timeline_events` table that no migration
   created before; databases that already have them are left unchanged:
   ```bash
   alembic upgrade head
   python scripts/check_schema_drift.py   # should report no missing tables or columns
   ```
4. Restart the backend and workers.
5. Encrypt credentials saved before this release:
   ```bash
   python -m src.backend.infrastructure.secret_box
   ```
   It prints how many workspaces it updated and never prints a credential.
6. Optional: set `WEBHOOK_SECRET_KEY` (already generated by `deploy/setup.sh`) so receivers can
   verify the `X-IntegrityDesk-Signature` header on finish notifications.

## Staging check (do before production)

Use two faculty accounts in the same organization (A and B) and one in another organization (C).

1. As A, create a course and run an analysis. Sign in as B: the course and analysis are not listed,
   and opening the analysis link directly shows "not found".
2. As A, open **Share** on the course and add B. As B: the course, its analyses and cases appear
   and can be edited. B cannot change the course's sharing.
3. As A, switch **General access** to "Everyone in your organization", then remove B. B still sees
   it (organization access); C does not.
4. As A, set it back to **Restricted** with nobody added: B no longer sees it.
5. In A's workspace settings, save an OpenAI key, then use **Remove saved API Key** and save: the
   status returns to "Not configured".
6. Turn on **Email the uploader when an analysis finishes**, run a small analysis, and confirm the
   email arrives with counts and a link but no student names.

## Draft notice to faculty

> **Subject: IntegrityDesk: your courses are now private by default**
>
> With this week's update, courses, analyses and cases in IntegrityDesk are visible only to their
> instructors. Colleagues who could see your courses before will no longer see them unless you
> share them.
>
> To share, open the course (or an analysis or case) and select **Share**. You can add specific
> colleagues or give everyone in your organization access. People you share with can view and edit,
> just like you. Only a course's primary instructors can change its sharing.
>
> Also new: you can check submissions against earlier offerings of the same course, and get an
> email when an analysis finishes. Both are under **Settings → Review & Workflow** and
> **Settings → System**.
>
> Questions: reply to this message.
